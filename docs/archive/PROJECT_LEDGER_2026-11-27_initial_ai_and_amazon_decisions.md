### 2026-11-27 — Amazon categorization automation switches (design decisions; no code change)

**Owner's choice:** Allow automatic categories only when product-to-charge linkage and category are clear. Add independent, obvious one-click on/off controls for **Automatic categorization** (all spending, not Amazon-only) and **AI categorization** (paid categorization calls). AI OFF must block new categorization API requests server-side, including manual previews and background paths; clarify that already-started requests may have cost. Preserve separate AI financial outlook/QAQC controls.
**Review consequence:** Existing Ledger Lite queue is derived from low-confidence/unassigned items and skips many already categorized purchases. With auto-category OFF, every spending purchase lacking a human-confirmed category should be eligible for manual Lite review even if Plaid/merchant rules populated a category; display inherited labels only as suggestions, never silently finalize them. Keep saved manual decisions, Notes, bank facts and item evidence intact; do not reset historical manual choices or duplicate purchases.
**Confirmed review policy:** With automatic categorization OFF, Lite shows spending purchases without a recorded **human category confirmation**; it does **not** requeue purchases manually categorized/confirmed by either household reviewer. Previously auto/provider-categorized purchases without human confirmation remain eligible; existing labels may be shown as suggestions only. Preserve prior manual edits, Notes and identity; never duplicate a charge. **Confirmed AI trigger:** When AI categorization is ON, loading authenticated Full Ledger runs one pass over all eligible uncategorized purchases not previously examined by AI (not just Amazon). Persist per-purchase outcomes, including "AI checked — unable to categorize" when not confident. No automatic repeat checks after reload, no timers, no Lite-triggered AI. With automatic categorization OFF, AI may save suggestions but cannot assign the final category. **Still pending:** exact review history window and spending ceiling for a large first-time backlog. No code/production state change; private deployment unchanged.

### 2026-11-27 — AI categorization triggered on owner Full Ledger load (discussion; no code change)

**Owner decision:** When AI categorization is ON, each authenticated Full Ledger load initiates one check of all unexamined, uncategorized purchases, across Amazon and other merchants, including the backlog. No paid category run on timers, Plaid/bank refresh, Amazon sync, display rerenders, or the spouse's Lite link. AI OFF prevents new paid category calls server-side (in-flight calls may still incur charges). Financial-analysis and QAQC AI are separate.
**Persisted outcome and abstention:** Each account-qualified purchase gets a durable AI status: categorized, suggested-only if automatic category application is OFF, or AI checked — unable to categorize if insufficient confidence. Leave inconclusive items unassigned for Lite; do not automatically retry them even after reloading, reimporting, restart or deploy. Explicit owner recheck can be separately considered. Failed, timed-out and unprocessed API attempts must not be marked examined; deduplicate concurrent owner-device loads and make saving results and reservation consistent. Never overwrite human-confirmed category choices.
**Implementation boundary:** Existing paid Amazon AI is manual-preview and accepts Amazon product Notes only; this broader trigger, durable review status and both switches are design requirements, not live functionality. Preserve private-data minimization and current per-request ceiling; define a visible aggregate spend cap and what to do with a large first-load queue before enabling paid batch work. Deferred items stay unreviewed. No code, production data, secrets or deployment changed; documentation-only, runtime checks not applicable.

### 2026-11-27 — Cost estimate and $0.08 approval gate for load-triggered AI (design only)

**Owner decision:** Before any paid category request on a Full Ledger load, calculate and display a conservative total cost estimate for all eligible, never-AI-reviewed purchases. If estimate <= $0.08, run automatically when the AI toggle is ON; if > $0.08, show purchase count and estimated maximum and obtain affirmative approval for **that run**. On refusal, leave all items eligible for next load, with zero API calls initiated. AI OFF always prohibits new categorization calls. No permission is inherited into later runs.
**Cost guardrail:** Estimate each bounded request using the deployed model's then-current input/output rates and maximum output tokens, aggregate before starting, and enforce the approved spending ceiling server-side, including multi-batch work. Never initiate another request when its conservative maximum could exceed remaining approval; leave deferred items unreviewed. Actual API bills can differ from estimates, including failed/in-flight requests; avoid promising perfect billing guarantees. Already confidently categorized or successfully examined-but-uncategorized purchases are not billed for a duplicate AI review.
**Scope:** Existing importer has a $0.05 per-request preflight ceiling but does not have this aggregate on-load approval flow. This is an unimplemented design decision. No application code, financial state, paid requests or deployment changed; no runtime checks required for documentation-only record.

### 2026-11-27 — Implement load-only category AI switches and $0.08 preflight (source work)

**Code:** Added separate private category-AI plan/run routes; only authenticated Full Ledger load initiates paid work when AI is ON. Server computes bounded multi-batch worst-case cost using GPT-6 Luna standard token rates, does not call provider for declines, and requires one-run approval above $0.08. The server reserves encrypted attempt identifiers before each call, persists confident categories or abstentions, and prevents unknown-outcome retries. Immediate AI OFF stops the next unpaid batch; in-flight request cannot be canceled retroactively. The automatic-category switch blocks Amazon import/category-rule assignment and makes provider-categorized but unconfirmed expenses available to Lite without requeueing human-confirmed ones. Lite annotations show abstentions/suggestions. Existing financial report/QAQC AI is unaffected.
**Limits:** No production bank data or credentials used in tests, and no private Render infrastructure change. This implementation relies on source-verified model pricing and cannot guarantee exact billing when the provider charges for failed/in-flight requests. Real Amazon browser compatibility and private Render deployment require separate acceptance. Relevant CI must pass before the release can be called merged.
